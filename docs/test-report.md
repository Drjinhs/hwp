# 설치·문서 테스트 결과

확인일: 2026-10-04. 아래 결과는 이 저장소를 수정한 Windows 환경에서 확인한 범위입니다. 다른 컴퓨터의 한글 자동화나 변환 성공을 보증하지 않습니다.

## 최종 시험 결과

사용자의 파일 접근 승인을 받은 표시 모드에서, 수정한 스크립트의 최종 샘플을 다시 생성했습니다.

제목·소제목·빈 문단이 구분되고 본문이 정상적으로 줄바꿈됩니다. 첫 실행에서 나타난 문단 합쳐짐을 `BreakPara`로 교정했으며, 이후 확인된 마지막 안내 문장의 어절 분리를 짧고 명확한 테스트 문구로 교정했습니다.

최종 시험의 로컬 결과는 `outputs/native-final-02`에 보관했습니다. 이 폴더의 `sample.hwpx`, `sample.hwp`, 각 형식의 PDF, `report.json`, `qa.json`이 검증 근거입니다. 테스트 문서는 이 공개 저장소에 포함하지 않으며, 아래 재현 명령으로 생성할 수 있습니다.

이 시험은 **텍스트와 기본 문단 서식을 가진 1쪽 문서**에 대한 확인입니다. 표·그림·수식·여러 쪽 문서와 자동 페이지 교정은 시험하지 않았습니다. 화면 검수는 최종 HWP/HWPX를 한글에서 다시 열어 출력한 PDF를 렌더링해 수행했으며, 한글 편집 화면의 직접 캡처 검수와 구분합니다.

## 같은 날 재시험: 사용자 접근 승인 방식

한글 창을 표시하고 사용자가 테스트 파일의 접근을 허용한 뒤, HWPX/HWP 저장과 재열기, 본문 확인, PDF 출력이 모두 성공했습니다. 두 형식은 각각 1쪽이었고, PDF에서 추출한 내용도 같았습니다. HWPX 구조 검사와 HWP 파일의 OLE 컨테이너 식별자 확인도 통과했습니다.

첫 PDF의 전체 페이지를 렌더링해 확인하니 문자열의 LF 줄바꿈이 실제 문단 나눔으로 처리되지 않아 제목과 본문이 이어져 있었습니다. 이를 `BreakPara` 액션으로 수정하고 제목·소제목·14pt/7pt 빈 문단을 명시하는 재시험을 완료했습니다. 아래 최초 시험 표의 미완료는 숨김 실행 당시의 기록이며, 최신 확인 결과와 구분합니다.

공식 ZIP에서 받은 보안모듈 DLL의 SHA-256은 `9ac5b97c47ac8aed1e8bca27a3eef39411361d8f68c262509f0c40a8f9d21bb6`이었습니다. DLL을 OneDrive 밖 임시 폴더로 복사하고 32비트 STA PowerShell에서 임시 등록했지만 `RegisterModule`은 `False`를 반환했습니다. 등록 실패를 성공으로 처리하지 않고 파일 접근 전에 중단했으며, 테스트용 등록값을 제거했습니다. 공식 모듈 DLL은 저장소에 포함하지 않습니다.

이 환경에서 확인된 해결 방식은 **한글 창 표시와 사용자의 파일 접근 승인**입니다. 무승인 자동화가 해결되었다고 주장하지 않습니다. 관련 한컴 안내: [숨김 창과 파일 접근 승인](https://forum.developer.hancom.com/t/c/1889), [한글 2024 모듈 등록 문제 점검](https://forum.developer.hancom.com/t/ai/3242).

COM 등록과 문서 입력 단계의 진행을 저장·변환 성공으로 간주하지 않았습니다. 저장 중 사용자에게 창 표시 여부를 확인했으며, 표시된 창이 없다는 답변을 받았습니다. 원인은 확정하지 못했습니다.

원래 스킬 제작 도구의 `quick_validate.py`는 PyYAML이 없어 실행하지 못했습니다. 추가 패키지를 설치하지 않고 직접 검사했습니다.

## 실제 HWPX 편집 테스트

한글 설치에 포함된 `공문서_양식_템플릿_일반.hwpx`를 원본으로 사용했습니다. 원본을 바꾸지 않고 별도 파일에 텍스트 한 곳을 `hwp 스킬 실제 HWPX 편집 테스트`로 바꿨습니다. 해당 문단의 줄 배치 캐시는 제거했습니다.

- 본문 변경 위치: `Contents/section0.xml`
- 나머지 12개 엔트리: 압축 해제한 내용의 바이트 동일성 확인
- 결과 텍스트: XML을 다시 읽어 수정된 문구 존재 확인
- 결과 ZIP/XML: `validate_hwpx.py` 통과
- 한글에서 열기·쪽수·스타일 참조 전체·출력 화면: 미확인

이 검사는 ZIP 압축 바이트나 모든 XML 직렬화의 원본 동일성을 보장하지 않습니다. 본문 XML은 재직렬화됩니다. 보고서 서식 전체를 교정한 테스트도 아닙니다. 한글에 포함된 양식 및 파생 테스트 파일은 이 공개 저장소에 게시하지 않았습니다.

정상 HWPX 양식을 보유한 사용자는 다음과 같이 로컬에서 재현할 수 있습니다.

```sh
python tools/package-smoke.py --template "원본양식.hwpx" --output "outputs/package-smoke/sample.hwpx"
```

결과 파일과 함께 `.report.json`이 생깁니다. 기존 출력 파일이 있으면 덮어쓰지 않고 중단합니다. 이 도구는 한 곳의 텍스트를 바꾸는 편집 시험용이며 일반 보고서 작성기로 사용하지 않습니다.

## 자동 테스트 재현

```sh
python install.py --check
python tools/check_skill.py
python -m unittest discover -s tests -v
```

설치 테스트는 임시 디렉터리를 사용합니다. 실제 개인 스킬과 사용자 문서를 덮어쓰지 않습니다. HWPX 검사기 테스트의 작은 ZIP은 **검사기용 합성 입력**이며 실제 한글 문서로 열렸다고 주장하지 않습니다. Windows 실행 파일 테스트는 다른 운영체제에서 건너뜁니다.

GitHub Actions 설정은 Linux·Windows에서 Python 3.10·3.12로 같은 검사를 실행하도록 추가했습니다. Actions의 원격 실행 결과는 [Actions 페이지](https://github.com/Drjinhs/hwp/actions)에서 확인합니다. 이 문서에 적힌 10개 통과는 로컬 Windows 결과입니다.

## 한글 자동화 시험 재현

Windows에 한글이 설치되어 있는 환경에서 아래 명령을 사용합니다. 실행할 때마다 새로운 출력 폴더를 지정하세요.

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\tools\native-smoke.ps1 -OutputDirectory .\outputs\native-test-01 -ShowWindow
```

스크립트는 새 COM 객체를 만들고 한국어 샘플을 입력한 뒤 HWPX/HWP 저장 → 저장 파일 재열기 → 본문 확인 → PDF 저장을 순서대로 시도합니다. 사용자의 기존 문서를 연결해서 편집하지 않습니다. 글꼴은 실제 설치 목록을 확인해 휴먼명조, 없으면 함초롬바탕을 사용하며 성공 보고서에 선택한 글꼴을 적습니다. 제목 20pt, 본문·소제목 14pt, 첫 구분용 빈 문단 14pt와 나머지 구분용 빈 문단 7pt를 적용하며 줄간격은 145%입니다. 이 샘플은 표·그림·여러 쪽을 포함하지 않는 기본 저장 시험용입니다.

`-ShowWindow`는 테스트 창을 표시합니다. 파일 접근 승인창이 나오면 경로가 이번 시험의 출력 파일인지 확인하고 사용자가 접근을 허용합니다. 예상하지 못한 복구·암호·매크로 창은 진행하지 않고 확인합니다.

공식 모듈을 별도로 준비한 환경에서는 `-SecurityModulePath "공식 DLL의 전체 경로"`를 선택적으로 사용할 수 있습니다. 이 옵션은 테스트 고유의 HKCU 등록값을 만들고 등록 결과가 참일 때만 진행하며, 종료 정리에서 고유 등록값을 삭제합니다. 영구 설치나 시스템 보안 설정 변경은 수행하지 않습니다. 강제 중단으로 정리가 실행되지 않았다면 이번 테스트에서 만든 `HwpSmoke_` 등록값을 확인해야 합니다. 등록이 실패하면 창 표시와 사용자 승인 방식으로 진행하세요.

예상하지 못한 창이나 응답 없는 대기가 발생하면 중단하고 한글의 상태를 확인하세요. 이 스크립트 자체에는 자동 타임아웃이 없으므로 성공 결과를 기다리며 무기한 방치하지 마세요. 사용 중인 다른 한글 프로세스를 일괄 종료하지 마세요. 이번 환경에서는 저장 단계가 대기하여 시험을 중단했습니다.

한글 Windows 자동화와 웹한글 API는 지원 범위가 다를 수 있습니다. 관련 원문은 [한컴 Windows 자동화 자료](https://github.com/hancom-io/devcenter-archive/tree/main/hwp-automation)에서 확인할 수 있습니다.
