## 1. 준비물과 지원 범위

| 준비물 | 필요한 경우 |
| --- | --- |
| 로컬 파일을 읽고 실행할 수 있는 Codex 환경 | 스킬 설치와 문서 작업 |
| Python 3.10 이상 | 설치기와 HWPX 구조 검사 실행 |
| 문서 원본 또는 양식 | 기존 문서 수정, 양식에 맞춘 제작 |
| 한글 프로그램 또는 확인된 변환 도구 | 바이너리 HWP 제작·변환 |
| 문서를 열 수 있는 프로그램 또는 렌더러 | 실제 페이지와 출력 검수 |
| 지정한 글꼴 | 글꼴과 쪽수의 정확한 재현 |

설치기와 포함된 구조 검사기는 Python 표준 라이브러리만 사용합니다. 추가 패키지는 필요하지 않습니다. 스킬 설치가 한글 프로그램·변환기 설치를 대신하지는 않습니다.

| 형식 | 작업 방식 |
| --- | --- |
| `.hwpx` | ZIP/XML 구조를 분석하고 편집합니다. 새 문서는 정상적으로 열리는 HWPX 양식이나 기본 문서를 활용합니다. |
| `.hwp` | 설치된 한글 자동화나 확인된 변환기를 활용합니다. 사용 가능한 도구가 있는지 먼저 확인합니다. |
| `.docx` | 한글 형식 작업의 입력·중간 형식으로 활용할 수 있습니다. DOCX만 필요한 작업은 별도 Word 문서 스킬을 사용합니다. |

원본 프롬프트에 적힌 개인 보고서 양식은 배포 파일에 포함되지 않습니다. 자신의 양식을 첨부하거나, 한글에서 만든 빈 문서를 HWPX로 저장해 제공하면 시작하기 좋습니다. HWP와 HWPX는 확장자만 바꿔서 변환할 수 없습니다.

## 2. 설치하기

### 방법 A. ZIP을 받아 Codex에 설치 맡기기

1. [GitHub 저장소](https://github.com/Drjinhs/hwp)에서 **Code → Download ZIP**을 선택합니다.
2. ZIP을 압축 해제합니다. `README.md`, `install.py`, `hwp` 폴더가 있는 위치를 확인합니다.
3. Codex에서 그 폴더를 작업공간으로 열거나, 전체 경로를 요청에 적습니다.
4. 다음 문장을 보내세요. 대괄호 부분은 자신의 경로로 바꿉니다.

```text
이 폴더에 있는 install.py를 확인하고 hwp 스킬을 설치해줘.
install.py --check로 배포 파일의 무결성을 먼저 확인한 뒤 설치하고,
설치된 5개 파일과 설치 경로를 확인해줘.
다른 스킬은 유지해줘. Python은 이미 설치되어 있어.
폴더: [압축을 푼 폴더의 전체 경로]
```

개인 스킬 폴더가 Codex 작업공간 밖에 있으면 파일 쓰기 승인이 표시될 수 있습니다. 이는 개인 스킬 위치에 설치하기 위한 권한입니다.

### 방법 B. 터미널에서 직접 설치

Windows에서는 터미널 명령 대신 저장소 폴더의 `install.cmd`를 더블클릭할 수 있습니다. 환경 진단과 무결성 검사를 실행하고, 설치 후 설치 상태를 확인합니다. 실패하면 창에 표시된 오류를 확인하세요. 실행 파일을 만들거나 패키지를 내려받지 않으며, 설치된 `py`, `python`, 또는 Codex 번들 Python을 사용합니다.

Git을 사용하는 경우:

```sh
git clone https://github.com/Drjinhs/hwp.git
cd hwp
python install.py --check
python install.py
```

ZIP을 받은 경우 `install.py`가 있는 폴더에서 마지막 두 명령만 실행하면 됩니다. Windows에서 `python`을 찾지 못하면 사용 가능한 `py` 또는 Python 실행 파일의 전체 경로로 바꿉니다.

```powershell
py install.py --check
py install.py
```

성공하면 무결성 검사에는 `OK: all five release files passed SHA-256 verification`, 설치에는 `Installed and verified:`와 실제 경로가 출력됩니다.

### 설치 위치와 기존 파일

| 환경 | 기본 설치 위치 |
| --- | --- |
| `CODEX_HOME` 설정됨 | `CODEX_HOME/skills/hwp` |
| `CODEX_HOME` 설정되지 않음 | 사용자 홈의 `.codex/skills/hwp` |

예를 들어 Windows 사용자 이름이 `myname`이면 기본 경로는 `C:\Users\myname\.codex\skills\hwp`입니다. 다른 사람의 사용자 경로를 그대로 사용하지 마세요.

기존 `hwp` 폴더가 있으면 설치기가 스킬 검색 경로 밖의 `skill-backups/hwp-날짜시간`에 복사한 뒤 배포 파일 5개를 갱신합니다. 기존 폴더의 그 밖의 파일과 다른 스킬은 삭제하지 않습니다.

사용자 지정 위치는 다음처럼 설정할 수 있습니다. Codex가 실제로 읽는 스킬 디렉터리를 선택하고, 마지막 폴더 이름은 `hwp`로 지정하세요.

```sh
python install.py --target "사용자지정경로/hwp"
```

### 설치 확인

새 Codex 작업을 열고 다음과 같이 요청합니다.

```text
$hwp 설치된 스킬의 이름과 지원하는 문서 형식을 확인해줘.
문서 파일은 아직 만들지 말아줘.
```

현재 작업에 바로 나타나지 않으면 새 작업을 열거나 Codex를 다시 시작한 뒤 확인합니다. 기존 `$hwpx`와 함께 설치되어 있어도 `$hwp`를 명시하면 원하는 스킬을 지정하기 쉽습니다.

터미널에서 환경과 설치 상태를 확인하려면 다음 명령을 사용합니다.

```sh
python doctor.py
python install.py --status
```

환경 진단은 Python의 실제 실행 경로, 기본 설치 위치, 한글 COM 등록 여부 등을 JSON으로 출력합니다. COM 등록은 자동화의 정상 실행을 보증하지 않습니다. 설치 상태 확인은 파일을 변경하지 않으며 현재 배포본과 다른 파일이 있으면 알려줍니다. 사용자 지정 위치는 `python install.py --status --target "경로/hwp"`로 확인하세요.

백업을 다른 위치에 저장하려면 `python install.py --backup-dir "백업폴더"`를 사용합니다. 백업 위치를 설치된 스킬 내부로 지정하면 실행이 중단됩니다.

## 3. 첫 문서 작업

가장 쉬운 시작은 **HWPX 양식 한 개와 작성할 내용**을 함께 제공하는 것입니다.

1. 한글에서 사용할 양식을 열고, 지원하는 경우 다른 이름으로 HWPX 형식에 저장합니다.
2. Codex에 양식과 작성 자료를 첨부하거나 전체 경로를 알려줍니다.
3. 문서 목적, 들어갈 내용, 결과 형식, 저장 위치, 유지할 서식을 적습니다.
4. 결과를 받아 한글에서 열고 모든 페이지를 확인합니다.

다음 요청을 복사해서 대괄호 부분을 바꿔 사용하세요.

```text
$hwp 첨부한 양식을 복사하여 [문서 제목]을 작성해줘.
목적과 독자: [보고 목적과 읽는 사람]
들어갈 내용: [핵심 내용 또는 첨부 자료 이름]
유지할 요소: 용지 여백, 제목 디자인, 표, 머리말·꼬리말
결과 형식: .hwpx
저장 위치와 이름: [전체 경로와 파일 이름]
원본은 유지하고 새 파일로 저장해줘.
구조 검증과 전체 페이지 출력 검수를 구분해서 결과를 알려줘.
```

쪽수 제한이 있다면 `최종 2쪽 이내로 작성해줘`처럼 추가합니다. 기존 문서의 쪽수를 유지해야 한다면 그 요구를 명시하세요. 서식이나 분량 조정만으로 만족하기 어려운 경우에는 Codex와 내용을 조정합니다.

## 4. 작업별 요청 예시

### 양식을 유지하여 새 보고서 작성

```text
$hwp 첨부 HWPX 보고서 양식을 사용해 AX 교육 운영계획을 작성해줘.
대상은 공공기관 실무자 30명이고 교육은 총 6시간이야.
목적, 교육 구성, 운영 일정, 기대 효과를 포함해줘.
양식의 제목·표·여백을 유지하고 결과는 운영계획.hwpx로 저장해줘.
확인되지 않은 예산과 날짜는 임의로 확정하지 말고 나에게 확인해줘.
```

### 기존 문서의 값만 변경

```text
$hwp 첨부 문서의 기관명을 [새 기관명], 날짜를 [새 날짜]로 바꿔줘.
본문과 표, 붙임에 있는 같은 항목도 확인해줘.
그 밖의 내용과 서식은 유지하고 수정본.hwpx로 새로 저장해줘.
```

### 회의록 작성

```text
$hwp 첨부 메모를 바탕으로 회의록을 작성해줘.
회의 개요, 주요 논의, 결정 사항, 담당자별 후속 조치를 구분해줘.
결정되지 않은 내용은 확정 사항으로 쓰지 말아줘.
한국어 실무 문서 기본 서식을 적용하고 회의록.hwpx로 저장해줘.
사용 가능한 양식이나 정상 기본 HWPX가 없으면 필요한 입력을 알려줘.
```

### 가독성 교정

```text
$hwp 첨부 보고서의 내용을 유지하면서 가독성을 교정해줘.
둘째 줄 내어쓰기, 구분용 빈 줄, 한두 음절만 남는 끝줄,
문단의 페이지 분리, 표 넘침을 모든 페이지에서 확인해줘.
최종 저장 파일을 다시 열어 확인하고, 미확인 범위도 알려줘.
```

### HWP가 반드시 필요한 경우

```text
$hwp 최종 결과가 .hwp여야 해.
먼저 이 컴퓨터에서 한글 자동화 또는 HWP 저장 가능한 변환기를 확인해줘.
사용 가능한 도구로 새 파일에 저장하고 최종 파일의 출력도 확인해줘.
도구가 없으면 다른 형식으로 완료 처리하지 말고 필요한 환경을 알려줘.
```

한글이 설치되어 있어도 자동화가 정상 작동하는지는 별도로 확인해야 합니다. 변환 도구가 없다면 HWPX로 받아 한글에서 직접 HWP로 저장하는 방법을 선택할 수 있습니다.

### 내용 읽기와 요약

```text
$hwp 첨부 문서의 본문과 표 내용을 읽고 핵심 내용과 누락된 입력값을 정리해줘.
원본 문서는 수정하지 말아줘.
```

## 5. 기본 서식과 변경 방법

한국어 실무 보고서·회의록을 작성하거나 가독성을 교정할 때 적용되는 기본값입니다. 현재 요청의 별도 지시를 우선합니다.

| 항목 | 기본값 |
| --- | --- |
| 본문 | 휴먼명조 14pt |
| 본문 줄간격 | 145%; 페이지 분리 교정 시 130~145% |
| `*`로 시작하는 부연설명·사례 | 중고딕 13pt |
| 첫 제목부와 첫 본문 사이 | 14pt 빈 문단 한 줄, 문서 처음 한 곳 |
| 그 밖의 문장·문단 구분 | 7pt 빈 문단 한 줄 |
| 이어지는 줄의 내어쓰기 | 첫 줄의 첫 단어 시작 위치에 맞춤 |
| 출력 검수 | 최종 저장 파일의 모든 페이지 |

7pt·14pt는 구분용 빈 문단의 글자 크기입니다. 줄간격의 백분율과는 별개입니다. 필요한 글꼴이 없으면 대체 글꼴을 확인하고 이름을 안내하도록 되어 있습니다.

다른 서식을 원하면 요청에 적으면 됩니다.

```text
$hwp 이번 문서는 본문을 함초롬바탕 12pt, 줄간격 160%로 작성해줘.
표와 제목은 첨부 양식의 서식을 유지해줘.
```

## 6. 결과 확인하기

Codex의 완료 보고에서는 결과 파일 경로, 결과 형식, 실행한 검증과 확인하지 못한 범위를 확인하세요.

### 구조 검사

HWPX 결과 파일은 다음 명령으로 검사할 수 있습니다. 명령은 내려받은 저장소 폴더에서 실행하며, 공백이 있는 파일 경로에는 따옴표를 붙입니다.

```sh
python hwp/scripts/validate_hwpx.py "결과파일의전체경로/result.hwpx"
```

정상인 경우 `OK: ... passed structural HWPX checks`가 출력됩니다. 오류가 있으면 `ERROR:`와 원인이 출력되며 종료 코드는 1입니다. 이 스크립트는 HWP 바이너리 검사에 사용하지 않습니다.

검사 대상은 ZIP 패키지, 주요 파일 존재, mimetype, XML 문법, 중복 엔트리와 일부 위험 경로입니다. 통과해도 내용 정확성, 모든 스타일 참조, 실제 쪽수와 화면 배치까지 확인된 것은 아닙니다.

### 내용과 화면 확인

실제 전달받은 최종 파일을 한글에서 다시 열어 모든 페이지를 살펴보세요.

- 이름·기관·날짜·금액과 결정 사항이 맞는지
- 원래 양식의 예시 내용이나 미입력 표시가 남아 있는지
- 제목·본문·주석의 글꼴과 간격이 의도대로인지
- 표·그림·머리말·꼬리말이 잘리거나 겹치지 않는지
- 제목이나 문단 끝의 짧은 한 줄이 다음 페이지에 홀로 남지 않는지
- 쪽수가 요청 조건에 맞는지

렌더러가 없는 환경에서는 Codex의 화면 검수가 미확인으로 남을 수 있습니다. PDF 변환본 검수는 변환 결과에 대한 확인이므로, 최종 HWP/HWPX의 한글 화면도 확인하는 것이 좋습니다.

## 7. 업데이트와 제거

### Git으로 설치한 사용자

저장소 폴더에서 실행합니다.

```sh
git pull --ff-only
python install.py --check
python install.py
```

직접 수정한 파일 때문에 갱신이 실패하면 수정본을 보존하고 차이를 확인하세요. 설치 후 새 Codex 작업에서 사용합니다.

### ZIP으로 설치한 사용자

최신 ZIP을 새 폴더에 압축 해제한 뒤 `install.py --check`와 `install.py`를 다시 실행합니다. 기존 설치는 백업되고 최신 5개 파일이 설치됩니다.

### 스킬 개선 요청

```text
hwp 스킬에서 [개선할 동작]을 수정해줘.
스킬 검증과 설치 파일 갱신도 해줘.
```

저장소 소유자가 Codex에 요청한 스킬 업데이트는 GitHub 갱신과 함께 진행하도록 유지보수 지침이 설정되어 있습니다. 다른 사용자의 컴퓨터에서는 GitHub 쓰기 권한이 자동으로 생기지 않습니다. 개선안을 공유하려면 [Issues](https://github.com/Drjinhs/hwp/issues)나 Pull Request를 이용할 수 있습니다. 파일 변경을 상시 감시하는 기능은 포함되어 있지 않습니다.

### 제거와 복원

실제 설치 경로를 먼저 확인한 다음, 설치된 `hwp` 폴더만 스킬 검색 경로 밖으로 옮기면 비활성화할 수 있습니다. 새 Codex 작업에서 적용 여부를 확인하세요. 다른 스킬 폴더는 그대로 둡니다.

이전 설치로 돌아가려면 현재 폴더를 보존한 뒤 `skill-backups`의 원하는 `hwp-날짜시간` 폴더를 설치 위치의 `hwp` 이름으로 복사합니다. 기본 백업 위치는 `CODEX_HOME/skill-backups` 또는 사용자 홈의 `.codex/skill-backups`입니다.

## 8. 문제 해결

| 증상 | 확인할 내용과 해결 방법 |
| --- | --- |
| `python` 명령을 찾지 못함 | `py` 또는 설치된 Python의 전체 경로로 실행합니다. 설치된 Python과 명령 검색 경로는 별개입니다. |
| `install.py` 파일을 찾지 못함 | 터미널 위치가 `install.py`가 있는 저장소 폴더인지 확인합니다. |
| `Integrity mismatch` | 파일이 수정되었거나 다운로드가 불완전할 수 있습니다. 공식 최신 배포본을 새로 받습니다. 단순히 체크섬만 바꿔 통과시키지 않습니다. |
| 설치 중 권한 오류 | 설치 위치를 확인합니다. Codex에서는 개인 스킬 폴더 쓰기 승인 요청을 확인합니다. |
| `$hwp`를 찾지 못함 | 설치 완료 경로와 `SKILL.md`를 확인하고 새 작업 또는 앱 재시작 후 다시 호출합니다. |
| 다른 한글 스킬이 선택됨 | 요청 첫머리에 `$hwp`를 명시하고 이 스킬을 사용하도록 적습니다. |
| 양식 없이 바로 만들 수 없음 | 정상 HWPX 양식이나 한글에서 저장한 빈 HWPX를 제공합니다. 별도의 문서 생성 실행기는 포함되지 않습니다. |
| HWP 저장을 수행할 수 없음 | 한글 자동화나 해당 HWP 저장을 지원하는 변환기를 확인합니다. HWPX로 전달받아 직접 저장할지 선택합니다. |
| 글꼴이나 쪽수가 달라짐 | 지정 글꼴 설치 여부, 변환에 따른 서식 변화, 최종 파일 렌더링을 확인합니다. |
| 구조 검사는 통과했지만 화면이 이상함 | 최종 파일의 전체 페이지 출력 검수를 요청합니다. 구조 검사만으로 배치를 판정할 수 없습니다. |
| 한글이 복구·암호·매크로 관련 창을 표시함 | 해당 메시지를 확인하고 Codex에 알려줍니다. 예상하지 못한 창을 무조건 닫거나 허용하지 않습니다. |
| 한글 자동화가 응답 없이 대기함 | 한글의 초기 실행·설정·권한 관련 창이 있는지 직접 확인합니다. COM 등록만으로 성공을 판단하지 않습니다. 사용 중인 한글 프로세스를 일괄 종료하지 않습니다. |
| 숨긴 한글에서 저장 호출이 멈춤 | 창을 표시해 테스트 파일의 접근 승인창을 확인합니다. 이 환경에서는 창을 표시하고 사용자가 승인한 후 저장·재열기가 성공했습니다. [재시험 결과](test-report.md)를 참고하세요. |

문제를 보고할 때는 사용 환경, 입력·출력 형식, 오류 문구와 재현 방법을 함께 적으면 도움이 됩니다. 문서 내용이 민감하면 공개 Issues에 원본을 올리지 말고 민감정보를 제거한 예제를 사용하세요.
